# Как это запускать

Короткий ответ на «что мне нажимать каждый день». Подробности по каждой команде — в
[`docs/OPERATIONS.md`](docs/OPERATIONS.md), сборка образа — в
[`docs/GOLDEN_IMAGE.md`](docs/GOLDEN_IMAGE.md).

## Главное про режим работы

**`vmfleet.ps1` — не служба, а разовая команда.** Его не «запускают и держат»: каждый вызов
(`status`, `up`, `down`, `clone`) отрабатывает и завершается. Поэтому запуск скрипта без
подкоманды просто спросит, какую команду выполнить:

```
cmdlet vmfleet.ps1 at command pipeline position 1
Supply values for the following parameters:
Command:
```

Это не ошибка — скрипту нужен аргумент (`status`, `up`, ...).

**Руками человек запускает ровно одно — агента.** Дальше парком управляет он: получает задачу
словами, сам вызывает `vmfleet.ps1` своим shell-инструментом, сам проверяет результат.

## Предусловия на хосте (один раз)

- Windows + **VMware Workstation** (нужен `vmrun.exe`; путь задаётся в блоке `CONFIG` внутри
  `vmfleet.ps1`);
- **PowerShell 7** (`pwsh`), не Windows PowerShell 5.1 — скрипт откажется стартовать под 5.1
  (`#requires -Version 7.0`);
- модуль разбора YAML:
  ```powershell
  Install-Module powershell-yaml -Scope AllUsers -Force    # от администратора
  ```
  Именно `AllUsers`, а не `CurrentUser`: модули PowerShell ставятся в профиль пользователя, и из
  другой учётки Windows оркестратор упадёт на «Модуль powershell-yaml не установлен»;
- **Claude Code** (или другой агент с доступом к shell на этом хосте);
- SSH-клиент (встроенный OpenSSH Windows подходит);
- собранный golden-образ и заполненный `inventory.yaml` (из `inventory.yaml.example`).

## Первый раз — разворачивание с нуля

Скопировать [`PROMPT.md`](PROMPT.md) целиком первым сообщением агенту. Он соберёт образ, настроит
оркестратор и, если нужно, развернёт первую проектную машину, спрашивая только то, что решать
действительно тебе (подсеть, пользователь SSH, секреты).

Вручную: `docs/GOLDEN_IMAGE.md` → блок `CONFIG` в `vmfleet.ps1` → `inventory.yaml.example` →
`inventory.yaml` → `docs/OPERATIONS.md`.

## Каждый день

```powershell
whoami                  # та же учётка Windows, под которой ставились модули
cd C:\vmfleet
.\vmfleet.ps1 status    # парк: вкл/выкл, расход ОЗУ, IP, готовые команды подключения
claude                  # дальше — словами: «подними машину X», «разверни проект Y»
```

`status` печатает готовые markdown-таблицы (включая колонку **Connect** с командами подключения к
каждой машине) — это сделано, чтобы вывод, который агент передаёт в чат, уже был таблицей, а не
разъезжался при пересказе.

## Ярлык — то же самое в один клик

Чтобы не набирать эти четыре строки каждый раз, есть [`make-shortcut.ps1`](make-shortcut.ps1) —
кладёт на рабочий стол ярлык, который сам открывает PowerShell 7 в каталоге оркестратора, печатает
статус парка и запускает агента:

```powershell
.\make-shortcut.ps1                                   # C:\vmfleet, ярлык на рабочем столе
.\make-shortcut.ps1 -FleetRoot D:\vmfleet             # свой каталог оркестратора
.\make-shortcut.ps1 -Startup                          # ещё и запуск при входе в Windows
.\make-shortcut.ps1 -Agent '' -NoStatus               # просто терминал в каталоге, без агента
```

Окно остаётся живым после выхода из агента (`-NoExit`), так что ручные команды парка можно набрать
там же.

## Если агента нет — руками

```powershell
.\vmfleet.ps1 up -Only <id>                 # поднять одну машину
ssh <id> -t 'tmux attach -t agents'         # agents.0 = инженер (слева), agents.1 = бюро (справа)
ssh <id>                                    # затем на госте: cd ~/workspace/project && devpanel
.\vmfleet.ps1 down -Only <id>               # погасить
```

## Что агент сделать не может — нужен живой человек

- пароль `sudo`, введённый в настоящем терминале;
- добавление deploy-ключа в настройках GitHub-репозитория;
- подтверждение UAC и правка системного `hosts` (нужны права администратора).

Такие места в документации помечены явно, обходных путей вокруг них не делается.

## Частые грабли

| Симптом | Причина | Что делать |
|---|---|---|
| `Supply values for the following parameters: Command:` | скрипт запущен без подкоманды | указать команду: `.\vmfleet.ps1 status` |
| «Модуль powershell-yaml не установлен», хотя он ставился | модули живут в профиле пользователя, окно открыто под другой учёткой Windows | проверить `whoami`, ставить модуль с `-Scope AllUsers` |
| Скрипт отказывается стартовать | запущен под Windows PowerShell 5.1 | запускать `pwsh` (PowerShell 7) |
| В выводе `status` кириллица как `?????` | консоль вызывающего процесса в кодовой странице 437 | скрипт сам выставляет UTF-8; проверить, что вызов идёт из `pwsh`, а не из `cmd.exe` |

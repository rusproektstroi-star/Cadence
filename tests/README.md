# Тесты

Два класса, не путать при отчёте о результатах:

- **pure** — чистая логика (парсинг, форматирование, валидация схемы), без VMware/vmrun/сети/
  реальных VM/systemd. Работает на любой машине с PowerShell/bash, включая CI. Ниже — только этот
  класс.
- **live** — сквозной прогон на реальном VMware-хосте с golden-образом (`vmfleet clone`, `devctl`
  на живой VM, кросс-ролевая маршрутизация панелей и т.п.). Не автоматизирован здесь — это ручная
  проверка по чек-листам `docs/ACCEPTANCE.md`, повторяется при значимых изменениях, не при каждом
  коммите.

Ни один pure-тест не подтверждает, что `vmfleet.ps1`/образ работают на реальном VMware-хосте —
только что их код/данные внутренне непротиворечивы. Зелёные pure-тесты — не то же самое, что
«живая система проверена», см. `docs/ACCEPTANCE.md` для второго.

## Версия Pester: нужна 3.x, на 5.x набор пока падает

Проверено 2026-09-20 на одной и той же машине: под **Pester 3.4.0** (тот, что идёт в комплекте с
Windows) — `Passed: 38 Failed: 0`; под **Pester 5.7.1** — 37 падений с `CommandNotFoundException`.

Причина не в самих проверках, а в их устройстве: тестируемые функции достаются из `vmfleet.ps1` по
AST и дот-сорсятся **прямо в теле `Describe`**. Pester 3 выполняет тело `Describe` и вложенные `It`
подряд, поэтому функции на месте. Pester 5 сначала обходит файл, собирая список проверок, и только
потом их выполняет — в теле `Describe` объявленное до фазы выполнения не доживает. Правильное
место для таких фикстур в Pester 5 — `BeforeAll`.

Переносится это не механически: часть переменных в тех же телах (`$yamlAvailable`) нужна именно на
этапе обхода, по ней стоит `-Skip`. Перенести всё разом — сломать пропуски. Отдельная задача, до
неё запускайте так:

```powershell
# гарантированно Pester 3 (штатный для Windows)
pwsh -NoProfile -Command "Import-Module Pester -MaximumVersion 3.99; Invoke-Pester -Path tests/vmfleet.Tests.ps1"
```
## `vmfleet.Tests.ps1` — PowerShell (Pester)

Покрывает: сам файл `vmfleet.ps1` парсится без синтаксических ошибок; каждая команда в
`ValidateSet` параметров имеет соответствующий case в диспетчере (и наоборот — не бывает
«мёртвых» case без входа в ValidateSet); `ConvertTo-MarkdownTable` (пустой вход, форматирование,
экранирование `|`); `Get-LocalRepoPath` (разбор SSH/HTTPS URL репозитория); схема
`inventory.yaml.example` (парсится, обе роли агентов на месте, нет дублей); `Invoke-Validate`
находит дублирующиеся `id` и `.vmx` вне `$VmxRoot` на специально сконструированном временном
инвентаре.

Тестируемые функции **не переписаны и не продублированы** — извлекаются из реального
`vmfleet.ps1` по AST (см. `Get-FunctionSource` в начале файла) и подгружаются изолированно, без
выполнения остального скрипта (который иначе потребовал бы физического `vmrun.exe` на диске и
интерактивного значения обязательного параметра `-Command`).

```powershell
# Модуль Pester идёt в комплекте с Windows PowerShell/pwsh. Для тестов инвентаря нужен ещё:
Install-Module powershell-yaml -Scope CurrentUser

Invoke-Pester -Path tests\vmfleet.Tests.ps1
```

## `golden-image/devpanel_test.sh` — bash

Покрывает: `pad()` (ручной паддинг по символам, не по байтам — см. `docs/decisions`-историю про
кириллицу в `devpanel`) и `load_config()` (разбор `.devpanel/services.conf`, включая пропуск
комментариев/пустых строк). Функции извлекаются из реального `golden-image/bin/devpanel` (`sed`
по границам объявления), не переписаны заново.

**Кириллический паддинг проверяется только на multibyte-aware сборке bash** (целевая Ubuntu —
подтверждено; некоторые сборки под Windows, в частности Git for Windows/MSYS2, считают `${#str}`
по байтам независимо от локали — это ограничение конкретной сборки bash, не баг `devpanel`). Тест
сам определяет эту возможность и явно помечает проверку как пропущенную на несовместимой сборке,
не выдаёт её за пройденную или проваленную.

`ss`/`systemctl`-зависимая часть `devpanel`/`devctl` (реальный статус процессов/портов) —
Linux-специфична, не тестируется здесь вообще, только на живой VM (`docs/ACCEPTANCE.md`).

```bash
bash tests/golden-image/devpanel_test.sh
```

# Промпт для разворачивания Cadence с нуля

Скопировать этот файл целиком в чат с Claude Code (или другим агентом с доступом к shell/
PowerShell на вашей Windows-машине с VMware Workstation) как первое сообщение — в директории,
куда склонирован этот репозиторий. Ниже — инструкция для АГЕНТА, не для человека; человеку нужно
только вставить её и отвечать на уточняющие вопросы по ходу.

---

Ты разворачиваешь Cadence — систему golden-образов и оркестратор для VM с ИИ-агентами (Claude
Code) — с нуля на этом хосте. Репозиторий уже склонирован, ты находишься в его корне. Прочитай
`README.md` целиком, потом `docs/GOLDEN_IMAGE.md` и `docs/OPERATIONS.md` — это твоя рабочая
спецификация, следуй ей буквально, не изобретай альтернативный порядок действий.

Действуй по шагам ниже. После каждого шага — короткое сообщение пользователю, что сделано и что
дальше, не молчаливая работа блоком. Если что-то требует решения, которое тебе не принадлежит
(реальный секрет, которого у тебя нет; необратимое действие) — остановись и спроси, не гадай.

## Шаг 0 — собрать вводные от пользователя

Прежде чем что-либо делать, узнай (спроси прямо, если не очевидно из окружения):

1. Где стоит VMware Workstation и где хранить `.vmx`-файлы гостей (диск/папка — то, что станет
   `$VmxRoot` в `vmfleet.ps1`).
2. Куда положить сам репозиторий `vmfleet`/оркестратор на хосте (обычно `C:\vmfleet` — можно и
   сам этот репозиторий, если он туда склонирован).
3. Есть ли уже базовая VM с Ubuntu Server (минимальная установка, SSH включён, без golden-пакетов)
   — если нет, это единственный шаг, который **ты не можешь сделать сам**: создание VM с нуля и
   установка ОС с ISO требует кликов в графическом инсталляторе VMware, недоступных тебе. Попроси
   пользователя: VMware Workstation → New Virtual Machine → Ubuntu Server (последний LTS ISO) →
   минимальная установка → включить OpenSSH server при установке → создать одного
   пользователя-владельца (его имя понадобится как `$SshUser`). Дождись, пока пользователь скажет,
   что VM готова и IP известен (`ip a` внутри гостя или DHCP-таблица роутера/VMware).
4. Какой SSH-пользователь и путь к владельческому ключу использовать (или сгенерировать новый
   `ssh-keygen -t ed25519` и попросить пользователя одобрить копирование публичного ключа на VM).
5. Подсеть VMware этого хоста — открой (или попроси открыть) VMware Virtual Network Editor,
   узнай DHCP-пул сети NAT/host-only, и какой диапазон вне пула использовать под статические
   адреса (`$StaticIpBase`/`$StaticIpRangeStart`/`$StaticIpRangeEnd`).

Не переходи дальше, пока не получишь эти пять пунктов — вся дальнейшая работа на них опирается.

## Шаг 1 — собрать golden-образ

Следуя `docs/GOLDEN_IMAGE.md` §1–§8 буквально (пакеты, Node.js, Claude Code, `devctl`, `devpanel`,
баннер, канон), выполнить каждый шаг по SSH на базовой VM из шага 0. Файлы, которые нужно скопировать
на гостя — в `golden-image/` этого репозитория (`scp`, не пересказ содержимого руками).

Обязательно выполнить §9–10 (обезличивание hostname/SSH host-ключей, и **чек-лист очистки перед
снапшотом** — без него любой последующий клон унаследует случайные тестовые данные). Это не
опциональный шаг, даже если сейчас это единственная копия образа.

Проверить (`docs/ACCEPTANCE.md` §1 — критерии, по которым сверяться): `tmux list-panes -t agents`
показывает две панели, обе `claude`; `gh auth status` — `not logged in`; `~/.bash_history` пуст.

Выключить VM (`vmrun stop <vmx> soft` из PowerShell) и сделать первый снапшот:
```powershell
& "C:\Program Files\VMware\VMware Workstation\vmrun.exe" snapshot "<путь-к-vmx>" "cli-golden-initial"
```

## Шаг 2 — настроить оркестратор

Открыть `vmfleet.ps1`, отредактировать блок «КОНФИГ» под значения из шага 0 (`$SshUser`,
`$SshOwnerKey`, `$VmxRoot`, `$StaticIpBase`/диапазон). Скопировать `inventory.yaml.example` в
`inventory.yaml`, вписать запись для `cli-golden` (`id: cli-golden`, `role: golden-template`,
реальный путь `.vmx`, `network.ip: null`).

Проверить:
```powershell
cd <путь к репозиторию>
.\vmfleet.ps1 validate
.\vmfleet.ps1 status
```
`validate` должен пройти без ошибок, `status` — показать `cli-golden` в инвентаре.

## Шаг 3 — первая проектная машина (если у пользователя уже есть репозиторий проекта)

Спросить у пользователя git-URL проекта и, если репозиторий приватный, путь к SSH deploy-ключу
(read или read-write — уточнить, нужен ли агенту `git push`) — **сам ключ пользователь генерирует
и добавляет в настройки GitHub-репозитория самостоятельно** (Settings → Deploy keys), это ровно
тот шаг, который требует реального секрета, недоступного тебе. Затем:

```powershell
.\vmfleet.ps1 clone <новый-id> -Repo <git-url> [-DeployKey <путь-к-ключу>]
```

Дальше — **по `docs/NEW_MACHINE_CHECKLIST.md`, целиком**, а не по памяти: там полный порядок
(статический IP, `ssh-config`/`hosts-file`, все поля записи в инвентаре, монтирование, проверка
того, что клон унаследовал настройки образа) и, главное, разбор того, что требует человека, а что
нет. В частности: **статический IP пароля не требует** — нужные команды разрешены без пароля,
проверять `ssh <id> "sudo -n -l"`, а не `sudo -n true`. Не звать пользователя туда, где он не нужен.

В конце показать финальный `vmfleet status` и команды подключения
(`ssh <id> -t 'tmux attach -t agents'`).

## Шаг 4 — доложить

Короткий итог: что развёрнуто, что подтверждено чек-листами `docs/ACCEPTANCE.md`, что осталось
на пользователя (создание deploy-ключей/токенов в GitHub UI — единственный класс шагов, который
в принципе не автоматизируется без передачи тебе чужих секретов).

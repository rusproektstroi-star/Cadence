# Cadence — чек-лист приёмки

Живая история проверки системы — что проверено, что нашлось по пути, что осталось открытым. Не
маркетинговый список «всё работает», а честный журнал: где стоит ✅ — проверено вживую, где ⏳ —
логика есть, живого прогона не было, где ⚠ — известное ограничение.

## 1. Профиль `headless` — golden-образ

| № | Критерий | Результат |
|---|---|---|
| 1 | Нет `code`/Xorg/Openbox, `systemctl get-default` = `multi-user.target` | ✅ подтверждено при сборке образа (`docs/GOLDEN_IMAGE.md`) |
| 2 | Замер ОЗУ простой/1 агент/2 агента задокументирован | ✅ замерено на реальном хосте; нагрузка "в работе" — не измерялась отдельно |
| 3 | `MAX_CONCURRENT` пересчитан по замерам, вариант зафиксирован с обоснованием | ⚠ плановое значение, не подтверждено полным парком (у вас будет свой замер под свою машину) |
| 4 | `start-agents.sh` — интерактивно/по SSH без TTY/без дублей | ✅ повторный запуск вывел «Сессия agents уже существует», панелей осталось 2, не 4 |
| 5 | `echo $CLAUDE_CONFIG_DIR` свой в каждой панели, не задан вне панелей | ✅ подтверждено через `/proc/<pid>/environ` каждого процесса `claude` |
| 6 | `gh auth status`/`git push` в проектную ветку отрабатывают | ✅ на реальном проекте |
| 7 | `ssh <id>` подключается по имени из инвентаря без правок | ✅ через `vmfleet ssh-config` |
| 8 | Весь парк в бюджете, своп не систематический | ⏳ зависит от размера вашего парка |

## 2. Оркестратор

| № | Критерий | Результат |
|---|---|---|
| 1 | `pwsh`/`claude`/`git`/`ssh` доступны, версии в логе | ✅ |
| 2 | Сессия-агент в директории оркестратора читает `CLAUDE.md`, ориентируется без вопросов | ✅ |

| 4 | Порог `MAX_CONCURRENT`/свободной ОЗУ — отказ, не деградация | ✅ отказ с понятным сообщением, до попытки старта |
| 5 | Замер: свободная ОЗУ хоста при полностью поднятом парке | ⏳ зависит от размера вашего парка |
| 6 | `ssh-config` даёт рабочий конфиг без ручных правок | ✅ существующие записи не тронуты, блок `vmfleet` создаётся/обновляется идемпотентно |
| 7 | Логи всех операций, воспроизводимая последовательность | ✅ `logs\YYYY-MM-DD.log`, метка времени + код возврата |

**Найденный и исправленный баг реализации** (существенно для любого, кто пишет похожий скрипт):
PowerShell разворачивает список из одного элемента в скаляр при фильтрации `Where-Object` —
`$targets.Count` на единственной подходящей машине считал число ПОЛЕЙ записи, не число машин.
Исправлено оборачиванием в `@(...)` везде, где список могло схлопнуть — см. код `vmfleet.ps1`.

| № | Критерий | Результат |
|---|---|---|

| 7 | Третий dev-сервер отклоняется с показом двух работающих | ⏳ нужна вторая машина со статическим IP для живого теста |
| 8 | Страхующий контур хоста при отключённом гостевом таймере | ✅ реализовано и зарегистрировано (`vmfleet-dev-watchdog`, задача планировщика) |
| 9 | Событие доходит до рабочего каталога агента | ✅ `.dev-events.log` подтверждён |
| 10 | Замер: N VM, 2 dev-сервера, освобождение ОЗУ после остановки | ⏳ зависит от размера вашего парка |

**Пункт 8 — закрыт после первой правки.** Изначально был реализован только `vmfleet dev-reap`
(ручной рычаг) — недостаточно само по себе. Добавлены `vmfleet dev-watchdog` (сравнивает
`idle_seconds` с удвоенным `GraceSeconds`, гасит и логирует «ТРЕБУЕТ ВНИМАНИЯ») и
`vmfleet install-dev-watchdog-task` (регистрирует задачу планировщика Windows, раз в минуту).

## 5. Сквозной тест — `vmfleet clone` на реальном проекте

Полный цикл `clone` (образ → сеть → deploy-ключ → репозиторий → автостарт агентов через `systemd`)
проверен несколькими прогонами. Найдено и исправлено:

| № | Баг | Статус |
|---|---|---|
| 1 | `-cloneName=$NewId` без кавычек не разворачивался | ✅ исправлено |
| 2 | Ни один `ssh`/`scp` не передавал `-i` — работало только через алиасы `~/.ssh/config` | ✅ исправлено (`$SshBaseOpts` везде) |
| 3 | Деидентификация host-ключей требовала пароль вне NOPASSWD-scope | ✅ исправлено (точный sudoers-список на образе, без wildcard) |
| 4 | `ssh-keygen -R $ip` стоял ПОСЛЕ первого обращения к новому IP, а не до | ✅ исправлено |
| 5 | `\r` в манифесте ролей из-за pipe многострочной строки в `ssh` (PowerShell-специфика) | ✅ исправлено (`echo` вместо pipe) |
| 6 | **Существенный**: golden-образ нёс живые логин-данные Claude Code (утечка из эмпирической проверки на раннем этапе) + `clone` не переименовывал hostname клона | ✅ исправлено — учётки вычищены перед каждым публикуемым снапшотом, hostname переименовывается в `clone` |

**Подтверждено сквозняком**: полный цикл `clone` реально работает — автостарт на ДЕЙСТВИТЕЛЬНО
свежем клоне проверен, не только на уже существующих машинах.

| Команда | Результат |
|---|---|
| `validate` | ✅ |
| `up -Only` / `down -Only` | ✅ (реальный подъём/гашение, IP получен, статус подтверждён) |

| `hosts-file` | ✅ честно требует администратора, не тихий пропуск |

| `activate` | ✅ отказывает без статического IP |
| `deactivate` | ⚠ минимальная заглушка сетевой части (сам подъём/гашение dev-сервера — через `devctl` на госте) |
| `check-sync` без `-LocalPath` | ✅ понятная ошибка, не тихий сбой |

**Переключение окон/панелей `tmux`** проверено через прямые эквиваленты (`new-window`/
`select-window`/`select-pane -L/-R`) — физическая прокидка клавиш от реальной клавиатуры
(`Ctrl+B` и т.п.) не проверяема ботом в принципе, только оператором. Создание/переключение/
закрытие окна и переключение панели по направлению работают корректно, сессии `claude` в
`agents.0`/`agents.1` не затрагиваются.

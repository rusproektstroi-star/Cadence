# Решение: монтирование рабочих каталогов агентам

Задача: дать оператору положить файл в рабочий каталог конкретного агента перетаскиванием в
проводнике, без команд и без путаницы между машинами. Основной сценарий — скриншот для визуальной
отладки, который агент должен увидеть.

## Модель

Каталог проекта физически на гостевой машине. SSHFS-Win показывает его хосту как сетевой диск:
запись уходит по SSH на диск гостя. Копии на хосте не остаётся, синхронизации нет, направление одно.

Одна машина — одна буква диска, закреплённая за проектом в инвентаре. При трёх и более активных
машинах это единственное, что отличает «положить агенту на dev-01» от «положить агенту на dev-02».

## Буквы дисков — с конца алфавита

`X`, `Y`, `Z`, затем `W`, `V`, `U`. Новые физические диски и флешки Windows нумерует от начала
алфавита, поэтому конец алфавита не отбирают у проектов закреплённые буквы. Валидатор проверяет и
уникальность буквы по парку, и то, что она не занята на хосте чужим устройством.

## Поля инвентаря

```yaml
    project: my-project
    github:
      own_repo: true                     # правило игнорирования, см. ниже
    host:
      mount_letter: "X"
      mount_label: "my-project"          # подпись диска — ИМЯ ПРОЕКТА, не id машины
      remote_path: "workspace/project"   # относительно $HOME гостевого пользователя
    guest:
      inbox_dir: "screenshots"           # каталог для файлов от оператора, внутри remote_path
```

**`remote_path` относительный, от `$HOME`.** Пользователь гостя задаётся один раз в конфиге
(`$SshUser`); абсолютный путь дублировал бы его в каждой записи инвентаря. UNC собирается как
`\\sshfs\<user>@<host>\<remote_path>`.

**`mount_label` — имя проекта.** При трёх активных дисках номер машины приходится вспоминать, имя
проекта опознаётся мгновенно. Отдельное поле (а не просто `project`) — на случай, когда имя
репозитория и рабочее имя проекта расходятся.

**Монтируется `remote_path`, а не `inbox_dir`.** Оператору регулярно нужны и остальные файлы
проекта, а не только каталог обмена.

## Правило игнорирования выбирается по инвентарю, а не угадывается

`github.own_repo: true` — строка `screenshots/` идёт в `.gitignore` и коммитится вместе с проектом.
`false` (репозиторий чужой или общий) — та же строка в `.git/info/exclude`: файл локальный, в
коммиты не попадает. Оркестратор читает поле и не решает это сам.

## Что оркестратор не делает

Не коммитит в проектный репозиторий. Блок про `screenshots/` (`canon/project-screenshots-block.md`)
дописывается в `CLAUDE.md` проекта на госте, если его там ещё нет, и остаётся незакоммиченным —
коммит делает инженер этого проекта. В отчёте об этом сказано явно, а не умолчано.

Последний пункт блока — «если оператор говорит „посмотри скриншот“ без имени, проверь каталог на
самый свежий файл» — не косметика: без него агент отвечает, что не видит вложений, вместо того чтобы
посмотреть в каталог.

## Подпись диска — через реестр, не `label`

Команда `label` работает с томами, а не с сетевыми дисками. Подпись сетевого диска задаётся ключом
`HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer\MountPoints2\<UNC в экранированном виде>\
_LabelFromReg`, где `\\sshfs\user@host\path` записывается как `##sshfs#user@host#path`. При
`unmount` ключ снимается вместе с монтированием — иначе подписи накапливаются от давно удалённых
дисков.

## Привязка к жизненному циклу — не «один раз и навсегда»

- `activate` монтирует, `deactivate` размонтирует;
- `down` размонтирует **до** выключения машины: выключение ВМ с живым монтированием оставляет
  зависший дескриптор, который снимается только перезапуском проводника;
- `/persistent:no` обязателен: восстановление диска при входе в Windows произойдёт раньше, чем
  поднимется ВМ, и проводник повиснет на первой же попытке его открыть. Это же и главная причина,
  по которой монтируются только включённые машины;
- осиротевшие монтирования (`\\sshfs\...`, которых нет в инвентаре) снимаются в `mounts` — с
  записью в лог, а не молча.

## Отсутствие предпосылок не валит `activate`

WinFsp и SSHFS-Win — инсталляторы с UAC, то есть шаг человека. Сетевая часть и dev-сервер от
монтирования не зависят, поэтому при отсутствующих предпосылках `activate` делает остальное и
печатает, чего не хватает; `mount` отказывает текстом со ссылками на установку, а не ошибкой
`net use`. Валить всю команду из-за необязательного удобства — неверно.

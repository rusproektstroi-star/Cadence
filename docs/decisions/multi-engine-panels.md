# Несколько движков в панелях: выбор модели для роли

**Статус:** работает на втором эталоне `cli-golden-multi`, снимок `multi-2026-09-23-gemini`.
**Проверено на месте:** `tmux 3.6` на машинах парка, команды `respawn-pane`, `display-popup`,
`display-menu` доступны (2026-09-22).

## Зачем

Две причины, и вторая практичнее первой.

**Лимиты.** Пятичасовое окно подписки выбирается двумя машинами за полтора часа. Самая
токеноёмкая роль — инженер, и если она работает на другом движке, она не тратит квоту Claude
вообще. Это дешевле доплаты и надёжнее для планирования.

**Коллаборанты.** Репозиторий сейчас предполагает Claude и только его. Возможность выбрать движок
на роль — то, ради чего проект может взять человек, работающий на другой платформе.

## Что делает это возможным почти даром

Панель в Cadence — **не Claude Code, а «агентский CLI в окне tmux»**. Оркестратор общается с
панелями через `send-keys` и `capture-pane` и не знает, что внутри. Значит поставить туда другой CLI
можно уже сейчас; недостаёт только способа выбрать и переключить.

## Решение по удобству — одна клавиша и всплывающая таблица

Выбрано оператором 2026-09-22 из трёх вариантов (всплывающая таблица, постоянная полоса снизу,
отдельное окно tmux).

**Суть задачи была не в переключении, а в том, ГДЕ набирать команду.** Пока CLI запущен, строка
ввода принадлежит ему: набранное уходит в модель, а не в оболочку. Ответ — не набирать в панели
вовсе: `tmux` перехватывает нажатия раньше программы, которая в панели работает.

```
Нажатие F9 в любой момент, хоть посреди генерации ответа:

┌─ движки · nft-server-v2 · панель: инженер ────┐
│  #  движок        состояние                   │
│  1  claude-code   ● работает здесь            │
│  2  gemini-cli    ○ готов                     │
│  3  qwen-code     ○ готов                     │
│  4  codex         ✗ нет ключа                 │
│  5  deepseek      ✗ не установлен             │
│                                               │
│  S 2  поставить в эту панель                  │
│  K    погасить движок в этой панели           │
│  Esc  закрыть                                 │
└───────────────────────────────────────────────┘
```

Почему этот вариант: экран не занимается постоянно, панели агентов не ужимаются, таблица приходит
по требованию и показывает состояние — какой движок где работает, какой установлен, у какого нет
ключа. Угадывать не нужно.

Клавиша привязывается **без префикса** (`bind-key -n`), чтобы не вспоминать `Ctrl-b`. Конкретную
клавишу подобрать при реализации так, чтобы она не конфликтовала с самими CLI.

## Чем переключается

`respawn-pane -k` — убивает то, что запущено, и стартует другое **в той же самой панели**. Не новое
окно и не новая панель: место и размер сохраняются, а значит канон «инженер слева, бюро справа»
остаётся в силе.

## Оркестратору это достаётся даром

Тот же скрипт вызывается по SSH, без входа в панель:

```
vmfleet.ps1 engine <машина> <роль> <движок>
```

Поэтому удобство человека решалось первым: программный путь из него следует, а не наоборот.

## Что сложнее самой кнопки

Три вещи, и они и есть настоящая работа.

**Канон роли у каждого движка свой.** `CLAUDE.md`, `AGENTS.md`, у остальных своё. Роль надо подавать
новому движку в том виде, который он читает, иначе он стартует без правил и без границ.

**Авторизация у каждого своя** — ключ или вход, своё место хранения. Ключи идут тем же путём, что и
все секреты парка: `secrets.env` на хосте, `bridge.env`-подобный файл на госте, никогда не в git.

**Переключение убивает сессию.** Память движка исчезает вместе с процессом. Спасает файл нити
работы, который агент ведёт по стоячему правилу: новый движок стартует, читает нить и продолжает с
того же места. Без нити переключение означало бы потерю работы — и тогда им нельзя было бы
пользоваться всерьёз. Нить писалась ради сжатия контекста, но оказалась условием смены движка.

## Что вскрылось при первом живом прогоне

Пять помех, и ни одна не видна была на локальной проверке — все нашлись только на машине.

**Движки не в `PATH`.** Парк ставит их через `npm -g`, префикс `~/.npm-global`, а в `PATH` этот
каталог попадает только из `~/.bashrc`. Всплывающее окно и вызовы по SSH его не видят, и таблица
показывала «не установлен» для стоящего движка. Скрипт добавляет каталог сам.

**Ключи не наследуются.** Всплывающее окно получает окружение сервера `tmux`, а не панели. Таблица
писала «нет ключа» у настроенного движка. Скрипт сам подхватывает `~/.config/*.env`.

**Опознание по имени процесса врёт.** `claude` виден как `claude`, а `gemini` — как `node`: движки
на Node маскируются под него. Смотреть надо, **чем панель была запущена** (`pane_start_command`), а
не как называется процесс, и искать вхождение имени, а не точное совпадение — команда обёрнута в
оболочку и кончается кавычкой.

**`respawn-pane` запускает программу напрямую, минуя `~/.bashrc`.** Движок поднимался в домашнем
каталоге вместо проекта и спрашивал, доверять ли папке, то есть вставал и ждал человека. Запуск
обёрнут в оболочку, которая встаёт в рабочий каталог и подхватывает ключи. Домашний каталог
подставляется при сборке строки: `tmux` передаёт команду как есть, и `$HOME` доезжал буквально.

**Первый запуск движка спрашивает про вход.** Gemini задаёт два вопроса подряд — способ входа и
подтверждение найденного ключа. Панель встала бы и ждала нажатия. Ответы пишутся в
`~/.gemini/settings.json`, ключ настройки — `security.auth.selectedType`. Узнать его формат угадыванием
не вышло: проще один раз ответить в панели и посмотреть, что CLI записал сам.

Общий вывод для следующих движков: **каждый новый движок требует одного живого прогона.** Установка
и таблица — это десять минут, а вот первый запуск почти наверняка упрётся во что-то своё: доверие к
каталогу, выбор способа входа, собственный формат настроек.

## Порядок работ

1. клон с эталона — испытания на нём, не на рабочих машинах;
2. два движка, не шесть: `claude-code` и один другой. Проверить переключение туда и обратно с
   сохранением нити;
3. таблица и клавиша;
4. подача канона роли под второй движок;
5. только после этого — остальные движки и раскатка в эталон.

## Что ещё не решено

- где хранится список движков — в инвентаре парка или отдельным файлом рядом с ним;
- показывать ли в таблице расход по движкам: для Claude числа уже есть (`usage-probe`), у других
  свои механизмы или их нет вовсе.
